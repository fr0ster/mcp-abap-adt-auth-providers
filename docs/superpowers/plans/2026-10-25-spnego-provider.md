# SPNego Provider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `SpnegoAuthProvider` (auth-providers) and the system token source `@mcp-abap-adt/auth-spnego-gssapi`, proved against a Kerberos stand before either is published.

**Architecture:** A token-source contract and a `spnego` error kind in interfaces-auth 8.0.0, its words in auth-errors; the provider asks an `INegotiateTokenSource` for a fresh token per request and checks it is Kerberos; the system source wraps the `kerberos` npm binding in a sibling package of this repository, made multi-package first.

**Tech Stack:** TypeScript, Jest, Biome; MIT krb5 and Apache `mod_auth_gssapi` in Docker; `kerberos` 7.x (napi).

**Spec:** `docs/superpowers/specs/2026-10-25-spnego-provider-design.md` (answers `docs/superpowers/2026-10-25-spnego-provider-goal.md`).

## Global Constraints

- Dependencies only as published on the registry; nothing built against an unpublished version of another repository; lockfiles regenerated by npm only; npm scripts only, never `npx`.
- Release order: interfaces-auth 8.0.0 → auth-errors (major) → this repository (auth-providers 7.0.0 and auth-spnego-gssapi first release, one release). Merge, tag and publish only on the owner's word; the owner publishes.
- Rules 1–8 of auth-providers (CLAUDE.md) hold for the provider; every refusal minted by auth-errors; no error's message, no token, no service principal in any refusal or log line.
- A fresh token for every request; nothing cached across requests.
- No regex over input; no timeouts and no retries of the package's choosing; nothing written to stdout; `process.env` never written.
- The published auth-providers has no native code, no install script and no dependency on auth-spnego-gssapi; neither package depends on the other.
- `kerberos` is built from source (`npm rebuild kerberos --build-from-source`), allowed by `allowScripts` for that one package, only in the jobs that need it; every other install is `npm ci --ignore-scripts`.
- Windows on arm64 is out. Live runs against ABAP, macOS and Windows with a real ticket are the second stage, not this plan.
- Docs: artifacts in English; CLAUDE.md changes only with the owner's approval of the text.
- Codex review before every merge; each repository's change is its own PR (one PR per task per repository).

## Review Focus

1. A source that answers a token which is NTLM *inside* SPNEGO — expected `spnego` `ntlm-token`, not a header written (Task C1 fixture, Task C2 test).
2. A `servicePrincipal` with a trailing space, two `@`, a Unicode host, or `HTTP/host@REALM` (the Kerberos form, not GSS) — expected `invalid-value` at construction (Task C2).
3. A source whose `token()` resolves after the parties' signal aborted — expected `aborted` for the moment, the late token dropped and never written (Task C2).
4. Truncated or oversized DER (a length beyond the buffer, a length of more than four bytes, nesting past the structure) — `unreadable`, no throw, linear time (Task C1).
5. The `kerberos` binding absent from `node_modules` (a consumer installed with `--ignore-scripts`) — `binding-unavailable`, not `source-failed` (Task C3).
