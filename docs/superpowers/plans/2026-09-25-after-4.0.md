# After 4.0: the deferred findings, closed — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close everything the 4.0.0 reviews deferred, so the package carries no known loose ends: remove the `bin/` commands that never ran from npm, give every refusal a message naming its rule (absent distinguished from more than one), make `bearerConfirmation` explain why each candidate failed, close the SAML 1.x and `idpInitiated` side doors, quote every document value in a message, fill the test gaps, speed up the e2e suite, and release as 4.1.0. Separately, fix one JSDoc in `@mcp-abap-adt/interfaces-auth` and release it as 2.0.1.

**Architecture:** No new modules, providers, exports or config fields. The validator (`src/validation/assertionValidator.ts`) gains one cardinality helper, `requireOne`, and its bearer-confirmation step is split into `readConfirmation` (the non-temporal sub-rules, in the spec's fixed order) and `describeRefusals` (the capped, per-candidate message). `signedNode.ts` splits its reference count and wraps xml-crypto's `loadSignature`. `saml2Utils.validateSamlConfig` refuses `idpInitiated` with `authnRequestId` at construction.

**Tech Stack:** TypeScript 5.9, Jest 30 via `npm test` (never `npx jest`), `@xmldom/xmldom` 0.9, `xml-crypto` 6.3.2, `@mcp-abap-adt/auth-mocks` 0.3.0 (`generateKeyMaterial`, `signXml`, `startMockSamlIdp`, `setVariant`, `visit`), Biome.

**Spec:** `docs/superpowers/specs/2026-09-25-after-4.0-design.md`

## Global Constraints

(Copied verbatim from the spec's Constraints.)

- Everything pluggable stays a strategy. Nothing writes to `process.stdout`.
  Imports come only from `interfaces-auth`, `interfaces-auth-sap` and
  `interfaces-utils`.
- Every new or changed rule has a test that goes red when the rule is
  deleted. A conjunction gets one mutation per half.
- Every test asserts a message fragment unique to its rule.
- Every behaviour change is documented in the README, CHANGELOG and
  `CLAUDE.md`. Stricter refusals are listed under "what now fails".
- `npm run test:stand` passes before the PR goes to review.
